# Unreal Engine 2 master protocol: Unreal Tournament 2004

This is the master protocol Unreal Tournament 2004 speaks, Epic's, and how
exmaster speaks it: `Exmaster.UE2` (wire format) and
`Exmaster.UE2.Master` (the master, TCP). GameSpy's protocol, which the
first Unreal Tournament speaks, is in [gamespy.md](gamespy.md). The
sources used here are:

- The UT2004 Linux server, 3369, as LinuxGSM installs it: its traffic
  against a master that logged every frame, and then against exmaster, on
  2026-10-28.
- OpenSpy's master for it (https://github.com/openspy/openspy-core,
  `code/utmaster`), which players use now.
- A master in Rust (https://git.fuxle.net/fuxle/ut2004-masterserver-proxy),
  which follows OpenSpy's.
- qstat's client for it (`ut2004.c`), and pyut2serverlist
  (https://github.com/cetteup/pyut2serverlist), a client in Python.

## Where UT2004 servers go

The stock `UT2004.ini` names Epic's masters,
`ut2004master1.epicgames.com` and `ut2004master2.epicgames.com`, port
28902, which Epic shut down in 2023. The community runs others, and
LinuxGSM's ini names three: `ut2004master.333networks.com`,
`ut2004master.errorist.eu` and `utmaster.openspy.net`. The list is in the
server's ini, host and port both:

```
[IpDrv.MasterServerLink]
MasterServerList=(Address="127.0.0.1",Port=28902)
```

The server connects to each master in the list. `UplinkToGamespy=True`
under `[IpDrv.MasterServerUplink]` also has it heartbeat GameSpy's master,
which is gone; set it to False.

| Port | Use |
|---|---|
| TCP 28902 | master: servers and clients |
| UDP 7777 | server: the game |
| UDP 7778 | server: queries, the game port's next |
| UDP 7787 | server: GameSpy queries, the game port + 10, with `UplinkToGamespy` |
| UDP 10777 | server: LAN queries |

## Frames and strings

Everything goes over one TCP connection in frames: a length, 4 bytes
little-endian, then that many bytes. Integers are 4 bytes little-endian.
A string is an FString: a compact index, its length, then that many
Latin-1 bytes with a trailing NUL, or, with a negative length, that many
UTF-16LE characters with a NUL character. UT2004 sends an empty string as
length 0, without the NUL.

A compact index has a sign bit (0x80), a "more" bit (0x40) and 6 bits of
value in its first byte, then up to three bytes of a "more" bit (0x80)
and 7 bits, and a last byte of 8 bits.

## The handshake

The master speaks first: a frame with a challenge string. qstat takes at
most 8 characters; exmaster sends 8 digits. The other side answers with:

| Field | Server, as captured | Client, as qstat sends it |
|---|---|---|
| string | MD5 of its CD key, in hex | the same |
| string | MD5 of the CD key and the challenge, in hex | the same |
| string | `UT2K4SERVER` | `UT2K4CLIENT` |
| int | version, `3369` | `3323` |
| byte | OS | OS |
| string | language, `int` | `int` |
| then | int stats ID (-1 without stats), byte | three ints (GPU, vendor, CPU speed), byte |

A server with no CD key file ("Couldn't open cdkey file.") sends hashes
all the same. Nothing can check them now: they were checked against
Epic's database. OpenSpy's master doesn't, and neither does exmaster.

The master answers `APPROVED`, as a string, followed for a client by an
int, 3, which qstat insists on (OpenSpy sends it, its meaning unknown).
A name it doesn't know gets `DENIED` and the connection closed.

Then a server sends a frame of two ints, whether it thinks it is behind
NAT and whether it uplinks to GameSpy too (`0 0` here). It waits for
the master's next frame before it heartbeats; without one it gives up
after 10 seconds ("Master server connection failed") and reconnects.
exmaster sends what OpenSpy's master sends: byte 1, then the ints 120,
7778, 7777, 7787. These look like the ports the master saw the server's
UDP traffic come from, as Epic's master may have found them; the server
on port 7757 heartbeat 7757 all the same, so it doesn't use them for
that. After that the server sends a frame `04` and an int, the version
of its packages (44), which exmaster doesn't answer, and heartbeats.

A client sends a verification string (qstat `!` and 32 zeros,
pyut2serverlist 32 hex digits), gets `VERIFIED`, and makes one request.

## Heartbeats

A heartbeat is a frame starting with byte 1. The server sends one every
60 seconds on the connection it holds open, whether or not anything has
changed, and closes the connection when it shuts down. This is what the
captured one holds (325 bytes):

| Field | Type | Captured |
|---|---|---|
| addresses | compact count, strings | none |
| server ID | int | 0 |
| IP | string | empty |
| port | int | 7757, the game port |
| query port | int | 0 |
| name | string | `exmaster test` |
| map | string | `DM-Rankin` |
| game type | string | `xDeathMatch` |
| players, max players | int, int | 0, 16 |
| ping, flags | int, int | 0, 0 |
| skill level | string | `0` |
| rules | compact count, then key and value strings | `ServerMode dedicated`, `AdminName`, `AdminEmail`, `ServerVersion 3369`, `GameStats False`, `MaxSpectators 2`, `MinPlayers 0`, `EndTimeDelay 4.00`, `GoalScore 25`, `TimeLimit 20`, `Translocator False`, `WeaponStay True`, `ForceRespawn False`, `mutator DMMutator` |
| players | compact count, then ID, name, ping, score, stats ID each | none |

These are the fields of UT2004's `ServerResponseLine`. A server with
stats sends their lines as frames starting with byte 2.

## How exmaster lists servers

A server is listed at the IP its connection comes from and the port its
heartbeat names. TCP has proved the IP; the port is the server's word,
but it only matters to clients, who query that IP. The query port is the
heartbeat's, or the game port's next when it is 0, as it is.

- Each heartbeat refreshes the entry, and the entry lasts as long as the
  connection: when the server closes it, the server is dropped. A
  connection that hasn't had a heartbeat listed for 150 seconds is
  closed, and its server dropped. Other frames don't count, nor do
  heartbeats that don't parse or that the store refuses, so a connection
  can only keep its slot by keeping a server listed.
- If the server reconnects and heartbeats while the old connection is
  still open, the new one takes the entry over. Heartbeats that still
  come on the old one don't change it, and the old one closing leaves
  it.
- A heartbeat is stored at most once every 10 seconds per connection; one
  that comes sooner waits for the 10 seconds to end, and a later one
  replaces it. Each store goes to the other nodes, so this bounds that.
- A heartbeat that names another port moves the server.
- Frames over 32 KB close the connection. The player list after the rules
  isn't read. The name is kept to 127 bytes, the map, game type and skill
  level to 63, and what the server is filtered by is cut too (below):
  each entry is copied to every list and to the other nodes.
- The master takes 256 connections at once in their handshake or with a
  client, and 4,096 servers' that are past their handshake, apart, so
  servers can't take the slots clients need. A server over the 4,096 is
  closed at the end of its handshake. An IP can have as many open as it
  can list servers (`max_per_ip`), and 8 more, and open 10 at once, then
  one a second. A connection is closed 15 seconds after it opened, unless
  it is a server's past its handshake.
- `max_per_ip` and `max_servers` apply as to the other masters. A
  refused server is tried again at each heartbeat, and its connection is
  closed after 150 seconds; UT2004 then connects again.

## The list

A client's request is a frame of one byte and what follows:

- `00`, a query: a byte, the number of filters, then for each a key and a
  value as strings and a byte, the comparison: 0 `=`, 1 `!=`, 2 `<`, 3
  `<=`, 4 `>`, 5 `>=`, anything else off.
- `01`, the message of the day: the master answers a string and an int 0,
  and closes. exmaster's is empty.

The answer to a query is a frame of an int, the number of servers, and a
byte 1, then a frame a server, then the connection is closed:

| Field | Type |
|---|---|
| IP | 4 bytes, in order |
| port, query port | 2 bytes each, little-endian |
| name, map, game type | strings |
| players, max players | a byte each |
| flags | int |
| skill level | string |

The flags are bits the browser shows icons by, as OpenSpy's master sets
them: 0 password (`GamePassword` True), 1 stats (`GameStats` True), 2 the
latest version (`ServerVersion` 3369), 3 non-dedicated (`ServerMode`),
4 InstaGib (mutator `MutInstaGib`), 5 standard (always), 6 UT Classic
(`MutUTClassic`).

Filters go by OpenSpy's rules. A key the server doesn't have matches.
`=` and `!=` compare text, case aside; the others compare the numbers
the values start with. The keys a server has are its first 32 rules,
in lower case and cut to 32 bytes, and these, and every value is cut to
64 bytes; a query's values are cut the same, and it has at most 32
filters:

| Key | Value |
|---|---|
| `gametype`, `mapname`, `hostname`, `category` | game type, map, name, skill level |
| `currentplayers`, `numplayers`, `maxplayers` | numbers |
| `freespace` | 1 if there is room, 0 if not |
| `password`, `stats`, `transloc`, `weaponstay` | the rules `GamePassword`, `GameStats`, `Translocator`, `WeaponStay` |
| `nobots` | true if `MinPlayers` is 0 |
| `nomutators` | true if it runs none |
| `standard` | true |

`mutator` compares as 0 if the server runs that mutator and 1 if not:
`=` asks for servers that run it, and `>` 0 for those that don't, which
is how qstat asks (`mutator=-MutInstaGib`).

Lists count against the same reply budget as the other masters', and an
IP gets 5 at once, then one every 3 seconds. The least a list costs is
reserved before it is made; the rest is paid 64 KB at a time before each
part is sent, waiting when the budget is spent. A list larger than the
budget's burst, 1 MB, goes out all the same, at the budget's rate,
within the client's 15 seconds.

## Not done

- The community message and the "Ownage" maps (request 3), and upgrade
  notices: the client's tabs for them get nothing.
- UT2003, whose client is `CLIENT`, and other Unreal Engine 2 games, such
  as Killing Floor, which LinuxGSM installs only with a Steam account
  that owns it. Their names are denied.
- Sending servers packages or match IDs (frames 4 and 3 from the master).
